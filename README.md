# File Storage REST API (MinIO S3 Integration)

Высокопроизводительное и безопасное REST API файлового хранилища, построенное на реактивном стеке **Spring WebFlux** с интеграцией облачного хранилища **MinIO (S3)** и **JWT-аутентификацией**. 

Проект спроектирован по принципу **WORM (Write Once, Read Many)** для гарантированного аудита операций загрузки, изменения и удаления файлов.

## 🚀 Стек технологий
* **Core:** Java 17, Spring Boot 3.x
* **Reactive & Web:** Spring WebFlux, Netty
* **Security:** Spring Security (Reactive), JWT (Stateless)
* **Data Layer:** Spring Data JPA, Hibernate, MySQL, Flyway (миграции)
* **Cloud Storage:** MinIO S3 (io.minio SDK)
* **Testing:** JUnit 5, Mockito, Reactor Test (StepVerifier), Testcontainers
* **DevOps:** Gradle, Docker, Docker Compose
* **Documentation:** OpenAPI 3.0 / Swagger UI

## 🏗️ Архитектурные особенности и паттерны безопасности

1. **Защита памяти от OOM (Streaming Upload):** Загрузка файлов реализована потоковым методом. Байты из сетевого сокета мелкими чанками транслируются на диск во временные файлы через `DataBufferUtils.write()`, исключая агрегацию контента в Heap/Direct Memory через `join()`. Временные файлы гарантированно очищаются в блоке `doFinally`.
2. **Мгновенная инвалидация токенов (Паттерн `tokenVersion`):** В сущность пользователя внедрено версионирование сессий. При логауте или изменении прав администратором `token_version` в БД инкрементируется, что мгновенно аннулирует старый JWT на уровне реактивного фильтра безопасности `JwtTokenFilter`.
3. **Строгое разграничение прав доступа:**
   * **ADMIN** — Полный доступ ко всем доменам системы.
   * **MODERATOR** — Просмотр пользователей, полный CRUD логов и файлов.
   * **USER** — Публичная регистрация, просмотр своего профиля, загрузка файлов для себя и чтение *только своей* истории событий. Изменение и удаление (`ARCHIVED`) файлов/аккаунтов для роли USER полностью заблокировано на уровне сервис-слоя (`FileSecurityChecker`).
4. **Консистентность распределенного состояния (Блок компенсации):** Сохранение метаданных файла и создание лога аудита (`Event`) объединены в атомарную JPA-транзакцию. В случае сбоя СУБД срабатывает реактивный компенсатор (`onErrorResume`), который автоматически удаляет физически загруженный файл из MinIO, предотвращая появление "зомби-файлов".
5. **Изоляция данных на уровне СУБД:** Метод получения всех событий системы для роли `USER` автоматически подменяется на кастомный запрос репозитория `findByUserId`, исключая утечку логов чужих пользователей.

## 🛠️ Быстрый запуск

### 1. Переменные окружения (.env / System)
Для работы приложения в продакшн-режиме необходимо задать обязательные секреты (локально подставятся безопасные дефолты):
* `JWT_SECRET` — строка подписи токенов (не менее 32 символов)
* `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` — реквизиты первого суперпользователя.

### 2. Развертывание инфраструктуры (Docker)
Запустите базу данных MySQL и контейнер MinIO:
```bash
docker-compose up -d
```

### 3. Сборка и запуск приложения
```bash
./gradlew clean build
./gradlew bootRun --args='--spring.profiles.active=dev'
```
*Локально активируется профиль `dev`, который автоматически инициализирует тестовую учетную запись `admin/admin123` через `CommandLineRunner`.*

## 📋 API Эндпоинты (Кратко)
* `POST /api/v1/auth/login` — Аутентификация, выдача JWT токена.
* `POST /api/files` — Загрузка файла в MinIO (Доступно всем авторизованным).
* `GET /api/files/{id}` — Получение метаданных файла (Владелец, Moderator, Admin).
* `DELETE /api/files/{id}` — Перевод файла в архив (Moderator, Admin).
* `GET /api/events` — Просмотр логов аудита (USER видит только свои, Admin/Moderator — все).
